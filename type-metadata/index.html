Go 类型元数据与对象布局：Go 1.26.5 源码分析

TIP

先抓住主干 Go 里每个具体类型在运行时都对应一个只读的类型描述符（internal/abi.Type，runtime 里别名 _type）。它回答四个问题：

  1. 这个类型的值占多少字节、怎么对齐（Size_/Align_）；
  2. 值的哪几个字是指针（PtrBytes + GCData 位图）——GC 靠它扫描；
  3. 两个值怎么比较、怎么哈希（Equal/Hash）——map 和 == 靠它；
  4. 它有哪些方法、名字叫什么（UncommonType/Str）——interface 和反射靠它。

值本身不存类型指针；类型信息只在”需要动态行为”的地方出现：interface、反射、map、GC 扫描。普通 int、结构体字段访问在编译期就确定了，运行时零开销。

为什么需要类型描述符

编译期类型信息在代码生成后大多消失了——x.f 访问结构体字段靠的是编译期确定的偏移，不需要运行时查类型。但有些事编译期定不下来：

  • GC：拿到一个堆对象地址，得知道它里面哪些字是指针，才能追踪引用、判断存活；
  • 接口/反射：var i any = x 之后，运行时要知道 i 里装的到底是什么、能不能断言成 T、有哪些方法；
  • map：用任意类型做 key 时，需要它的哈希函数和相等函数；
  • 栈扫描：栈帧里哪些位置存了指针，由编译器生成的栈图给出，堆对象则靠类型描述符的位图。

所以每个非泛型实例化后的具体类型，链接器都会生成一份只读描述符。runtime._type 就是 internal/abi.Type 的别名，runtime、reflect、编译器共用同一份布局。

abi.Type 的核心字段

// internal/abi/type.go (Go 1.26.5)
type Type struct {
    Size_       uintptr                          // 值的字节大小
    PtrBytes    uintptr                          // 前缀中可能含指针的字节数
    Hash        uint32                           // 缓存的类型哈希
    TFlag       TFlag                            // 附加标志
    Align_      uint8                            // 变量对齐
    FieldAlign_ uint8                            // 结构体字段对齐
    Kind_       Kind                             // 类型种类（Bool/Int/Slice/Struct...）
    Equal       func(unsafe.Pointer, unsafe.Pointer) bool
    GCData      *byte                            // 指针位图
    Str         NameOff                          // 类型名偏移
    PtrToThis   TypeOff                          // 指向本类型的指针类型（0 表示无）
}

逐组看：

  • 大小与对齐：Size_、Align_、FieldAlign_ 决定对象布局和 unsafe.Sizeof/Alignof 的结果。
  • 种类：Kind_ 是 Bool/Int/.../Struct/Slice/Map/Chan/Interface/...。运行时用它做类型断言检查、选择专用描述符（比如 maptype）。
  • 比较与哈希：Equal 是这个类型的相等函数（不可比较类型为 nil）。map 的哈希值在类型里也有缓存（Hash 字段是结构哈希，运行时哈希算法在 runtime/alg.go）。
  • 指针信息：PtrBytes + GCData，下一节详述。
  • 名字与方法：Str 是名字偏移；TFlag&TFlagUncommon != 0 时，类型头后面紧跟一个 UncommonType，存方法集和包路径。
  • TFlag 关键标志：
    • TFlagNamed：有命名类型；
    • TFlagUncommon：后面带 UncommonType；
    • TFlagRegularMemory：值可当一段连续内存做 memequal/memhash（典型如纯数值数组）；
    • TFlagDirectIface：值能直接塞进 interface 的一个字（即 Size_==PtrBytes==goarch.PtrSize，如指针、channel、map、func）。

指针位图：GC 怎么知道哪里有指针

GC 扫一段内存时不能逐字猜”这是不是指针”。每个类型用一张位图回答：

  • PtrBytes 是值的前缀中可能含指针的字节数。前缀之后的部分 GC 直接当纯数据不扫描。比如 struct { p *int; x [1024]byte }，PtrBytes 只覆盖到 p，后面的大数组不进位图。
  • GCData 指向一个 bit 串，每个 bit 对应一个机器字，1 表示该字是指针、0 表示不是。位图按值的布局逐字标记，嵌套结构体/数组会被展开。
  • 若设了 TFlagGCMaskOnDemand，GCData 是一个间接字节，真正的位图在运行时按需构造（泛型实例化等场景用来节省体积）。

这就是”GC 是精确的、不是保守的”基础——它不会把一个恰好长得像指针的整数当根。栈上的局部变量则用编译器生成的栈图（FUNCDATA/PCDATA），不走 GCData，但思想一致。

UncommonType：方法挂在哪里

类型描述符的公共部分不直接带方法表。只有命名类型、或需要方法集时，才在类型专用头后面追加一个 UncommonType：

type UncommonType struct {
    PkgPath NameOff  // 包路径（内置类型为空）
    Mcount  uint16   // 方法总数
    Xcount  uint16   // 导出方法数
    Moff    uint32   // 到方法数组的字节偏移
}
type Method struct {
    Name NameOff     // 方法名
    Mtyp TypeOff     // 方法签名类型
    Ifn  TextOff    // 接口调用时用的函数（T.fn 形式）
    Tfn  TextOff    // 普通方法调用时用的函数
}

方法表是按名排序的数组，interface 查找时二分查找。Ifn 和 Tfn 的区别：如果方法不需要接收者解引用/不需要触发编译器生成的包装，两者指向同一个函数；否则 Ifn 是生成的适配闭包（见 Interface 笔记）。

不同 kind 的类型头不同：structtype 带字段数组、interfacetype 带方法数组、maptype 带 key/elem 类型指针。它们都以 Type 开头，所以任何类型指针都能当成 *Type 读公共字段，再按 Kind_ 转成具体类型。

对象在内存里怎么摆

类型描述符决定值的布局，规则简单：

  • 对齐：每个字段按其 Align_ 对齐；结构体整体对齐取字段最大对齐，大小是对齐的整数倍（尾部可能有 padding）。
  • 顺序：字段按声明顺序排列，但编译器不做重排（与某些语言不同）——要省空间得自己手动调整字段顺序。
  • 零大小类型：struct{}、[0]T 大小为 0。作为结构体最后一个字段时，Go 会额外补 1 字节，避免取其地址越界到别的对象；作为唯一字段或非末尾字段时可能零分配。
  • 空接口/接口：两个字大小（类型指针 + 数据指针）；TFlagDirectIface 的类型直接把值放进数据字（如 *T、chan、map），其他类型则数据字是指向堆/栈值的指针。
  • 字符串/切片/slice header：字符串是 {data, len} 两字；切片是 {data, len, cap} 三字；map/chan/func 在用户侧都是一个字的指针。
type Demo struct {
    A bool     // offset 0, size 1
    B int64    // offset 8（前补 7 字节 padding）
    C *int     // offset 16
}            // Size_=24, PtrBytes=24, Align_=8

边界与误区

  • Kind 不做掩码：Go 1.26 里 t.Kind() 直接返回 Kind_，没有 kindMask；种类判断用 k == KindStruct 等直接比较。
  • 命名类型和未命名类型是两个描述符：type MyInt int 和 int 是不同 *Type，但底层 Kind_ 相同、内存布局相同。
  • 接口里的”类型”是动态类型：var r io.Reader = w，接口里存的是 w 的具体类型描述符（可能是 *os.File），不是 io.Reader 自己。
  • GCData 只覆盖前缀指针区：PtrBytes 之后的字节保证无指针，把大的非指针数据放后面能缩小位图、加速扫描。
  • 方法集不在 Type 公共头里：反射拿方法要走 Uncommon()，且仅当 TFlagUncommon 存在。
  • 类型描述符是只读、全局唯一、可指针比较：两个接口值的动态类型是否相同，直接比 *Type 指针即可。
