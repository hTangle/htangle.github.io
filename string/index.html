字符串：Go 1.26.5 源码分析

[!abstract] 一句话理解 Go string 是不可修改的只读字节序列，运行时由数据指针和字节长度构成。它不保证内容是 UTF-8；len 和下标处理字节，range 才按 UTF-8 解码 rune。

本文以 Go 1.26.5、提交 c19862e5f8415b4f24b189d065ed739517c548ba 为准。相关主题：数组、切片、内存分配器、垃圾收集器。

1. 运行时表示

运行时结构见 runtime/string.go#L290-L303：

type stringStruct struct {
    str unsafe.Pointer
    len int
}

在 64 位平台，字符串值通常是 16 字节。复制字符串只复制指针和长度，不复制全部字节；字符串本身没有 Cap，也没有原地 append。

内部可保活版本的等价布局见 internal/unsafeheader.String#L28-L37。业务代码不要依赖 reflect.StringHeader.Data uintptr 管理对象生命周期。

2. 字节、rune 与 UTF-8

s := "Go语言"
fmt.Println(len(s))         // 8 字节
fmt.Println(utf8.RuneCountInString(s)) // 4 个 rune
fmt.Printf("%x\n", s[2])   // “语”的第一个 UTF-8 字节

三个层次必须分开：

概念Go 类型/操作含义
bytebyte、s[i]、len(s)原始字节
runerune、for rangeUnicode 码点
字形簇需额外 Unicode 分段库用户眼中的一个字符，可能含多个 rune

range 每轮返回当前 rune 的起始字节索引和解码结果；遇到非法 UTF-8 时返回 utf8.RuneError，并按 1 字节前进。

s := "A界"
for i, r := range s {
    fmt.Printf("byteIndex=%d rune=%U\n", i, r)
}
// byteIndex=0 rune=U+0041
// byteIndex=1 rune=U+754C

IMPORTANT

string 不验证 UTF-8 string([]byte{0xff}) 完全合法。网络协议、文件格式和数据库字段是否要求 UTF-8，应在边界处显式校验 utf8.ValidString。

3. 不可变性到底约束什么

Go 语法不允许修改字符串中的字节：

s := "hello"
// s[0] = 'H' // 编译错误

不可变性带来：

  • 多个 string 可安全共享同一字节存储；
  • 字符串可比较、可作为 map key；
  • 哈希和比较无需担心内容被合法 Go 代码原地修改；
  • 子串可只复制头部而共享原字节区。
whole := strings.Repeat("x", 1<<20)
part := whole[:8] // 可能仍保留整块 1 MiB 存储
part = strings.Clone(part) // 需要长期保存小子串时切断引用

[!danger] unsafe 会破坏语言保证 使用 unsafe.String 让 string 指向可变 []byte 后再修改该切片，会破坏不可变性，可能导致数据竞争、map key 失效和难以复现的错误。只有在能证明所有权、只读性和生命周期时才考虑零拷贝。

4. 字符串常量与生命周期

字符串字面量的字节通常进入程序只读数据；动态构造的字符串数据则可能位于栈或堆。header 指向哪里是编译器和运行时实现细节，不能用“字符串一定在只读段”概括所有 string。

运行时会检查不能让逃逸字符串错误地引用已经失效的栈数据，例如拼接只有一个非空操作数时的处理见 concatstrings#L44-L59。

5. 拼接：concatstrings

编译器把 a + b + c 降为 concatstring2 到 concatstring5 或通用 concatstrings。核心源码见 runtime/string.go#L17-L79。

若逃逸分析证明结果不逃逸，编译器可传入 32 字节临时缓冲区；rawstringtmp 会优先使用它，见 tmpStringBufSize#L17-L28 和 rawstringtmp#L184-L192。

循环拼接仍可能反复分配和复制：

var out string
for _, p := range parts {
    out += p
}

已知会多次写入时使用 strings.Builder：

var b strings.Builder
b.Grow(totalBytes)
for _, p := range parts {
    b.WriteString(p)
}
out := b.String()

strings.Builder.String 用 unsafe.String 返回内部 buffer 的只读视图，因此非零 Builder 不能按值复制；copyCheck 会检测非法复制。

6. []byte 与 string 转换

6.1 []byte → string

一般语义是复制字节，从而保证之后修改原切片不会改变字符串：

b := []byte("hello")
s := string(b)
b[0] = 'H'
fmt.Println(s) // hello

运行时入口 slicebytetostring#L133-L174：

  • 长度 0 直接返回空串；
  • 长度 1 可复用静态单字节表；
  • 不逃逸且长度不超过 32 字节时可用栈上临时缓冲；
  • 其他情况分配目标内存并 memmove。

编译器能证明转换只用于临时只读场景时，可能使用零拷贝临时形式 slicebytetostringtmp#L194-L222，例如某些 map 查询、比较和拼接。它是编译器优化，不改变语言层面的独立值语义。

6.2 string → []byte

一般语义同样创建可修改副本。运行时 stringtoslicebyte#L224-L234 选择栈上临时缓冲或新 byte slice，然后 copy 字节。

6.3 rune 转换

[]rune(s) 需要先数 rune 再分配并解码，见 stringtoslicerune#L236-L258。string(runes) 先计算 UTF-8 目标字节数，再编码，见 slicerunetostring#L260-L288。两者都不是 O(1) 头部转换。

7. 比较、查找与 map key

字符串相等比较先利用长度快速排除，再比较字节；排序比较是按字节字典序，不是按语言学排序规则。

字符串作为 map key 时，哈希对象是当前字节序列。短暂查询不必手工把 string 转换缓存为 []byte；当前编译器已能优化若干临时 string(b) 查询场景。

对于用户可控的大量 key，仍要关注：

  • key 总字节数和基数；
  • 重复字符串是否被业务层无界保留；
  • 规范化规则是否一致，例如大小写、Unicode normalization；
  • 不要用 unsafe 可变别名制造 map key。

8. 并发语义

合法 Go 代码不能修改字符串字节，所以多个 goroutine 并发读取同一 string 数据安全。但如果它们并发读写同一个 string 变量，header 的赋值仍需同步。

var current string
// 一个 goroutine 写 current，另一个读 current：没有同步就是数据竞争

可按场景使用 mutex、channel 或 atomic.Pointer/atomic.Value 安全发布。涉及 unsafe 零拷贝时，原始 buffer 的任何并发修改都会重新引入数据竞争。

用真实负载验证：

go test -bench=. -benchmem ./...
go test -run='^$' -bench=BenchmarkText -memprofile=mem.out
go tool pprof -alloc_objects mem.out
go build -gcflags='-m=2' ./...

10. 常见误区

[!failure] len(string) 是字符数 错。它是字节数。码点数使用 utf8.RuneCountInString，用户可见字符还需要字形簇算法。

[!failure] string 永远位于只读数据段 错。字面量通常如此，动态拼接和转换得到的数据可能在栈或堆。

[!failure] string 与 []byte 转换一定堆分配 错。语义通常要求复制，但编译器可使用栈缓冲或在严格临时只读场景消除复制。以逃逸报告和基准为准。

[!failure] strings.Builder.String 会复制完整字符串 当前实现直接返回内部 buffer 的 string 视图，因此 Builder 有严格的复制和后续使用约束。
