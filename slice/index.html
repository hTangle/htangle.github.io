切片：Go 1.26.5 源码分析

[!abstract] 一句话理解 切片是一个 Data + Len + Cap 的小型描述符。复制切片只复制描述符；多个切片可以共享底层数组；append 只有在容量不足时才分配新数组。

本文以 Go 1.26.5、提交 c19862e5f8415b4f24b189d065ed739517c548ba 为准。相关主题：数组、字符串、内存分配器、垃圾收集器。

1. 运行时表示

运行时内部结构见 runtime/slice.go#L16-L20：

type slice struct {
    array unsafe.Pointer
    len   int
    cap   int
}

在 64 位平台，切片描述符通常是 24 字节。len 约束索引，cap 约束扩展切片。它们都不表示底层数组已经使用了多少元素。

WARNING

reflect.SliceHeader 操纵生命周期 uintptr 不会让对象保持存活。需要底层指针时优先使用 unsafe.SliceData，构造切片使用 unsafe.Slice，并严格满足 unsafe 的生命周期和边界约束。内部等价布局见 internal/unsafeheader#L16-L26。

2. nil、空切片与零值

var a []int          // nil，len=0 cap=0 Data=nil
b := []int{}         // 非 nil，len=0 cap=0
c := make([]int, 0)  // 语义上非 nil 空切片

三者都能 append、len、range。差异主要出现在：

  • s == nil；
  • 某些 JSON 或协议编码；
  • API 是否用 nil 表示“缺失”、空切片表示“明确为空”。

切片只能与 nil 比较，不能直接比较两个切片。内容比较使用 slices.Equal 或业务自定义规则。

3. 创建：字面量、make 与切片表达式

3.1 字面量

s := []int{10, 20, 30}

编译器先准备一个数组，再构造指向该数组的切片。对应降级入口见 slicelit#L290-L414。底层数组可能在静态区、栈或堆，取决于上下文和逃逸分析。

3.2 make

a := make([]int, 5)      // len=5 cap=5
b := make([]int, 5, 10)  // len=5 cap=10

语义要求 0 <= len <= cap。运行时 makeslice#L101-L118 计算 cap * sizeof(T)、检查溢出并调用分配器：

Go 1.26.5 编译器还会尝试把部分变量容量的 make 转换为“阈值内走栈上数组，否则调用 makeslice”，源码见 walkMakeSlice#L423-L540。是否成功仍以编译结果为准。

3.3 切片表达式

对 a[low:high]：

new.Data = &a[low]
new.Len  = high - low
new.Cap  = cap(a) - low

三索引表达式 a[low:high:max] 还能限制容量：

new.Len = high - low
new.Cap = max - low
buf := make([]byte, 100)
frame := buf[10:20:20] // len=10 cap=10
frame = append(frame, 1) // 必须换底层数组，不会覆盖 buf[20]

4. 共享底层数组与别名

base := []int{1, 2, 3, 4}
x := base[1:3]
y := x
y[0] = 99
fmt.Println(base) // [1 99 3 4]

函数按值接收切片时也只复制三个字段，因此函数内能修改既有元素；但函数内 append 后得到的新描述符不会自动写回调用方。

func add(s []int) {
    s = append(s, 7) // 只更新局部 s
}

func addOK(s []int) []int {
    return append(s, 7)
}

[!danger] 子切片可能保留大对象 一个只剩几字节的子切片仍可能引用整个大底层数组，阻止其回收。需要长期保存小片段时使用 bytes.Clone、slices.Clone 或显式 copy。

5. append 的两条路径

编译器对 append 的核心展开形态见 walkAppend#L22-L127：

newLen := len(s) + added
if newLen <= cap(s) {
    s = s[:newLen]
} else {
    s = growslice(s.ptr, newLen, s.cap, added, elemType)
}
// 把新增元素写入尾部

因此，不能根据语法判断 append 是否分配；必须结合当前 len/cap、元素大小、逃逸和编译器优化。

6. growslice 与容量算法

growslice#L134-L287 完成四件事：

  1. 计算至少容纳 newLen 的逻辑容量；
  2. 按元素大小和分配器 size class 对齐实际字节数；
  3. 分配新底层数组；
  4. 将 [0:oldLen] 搬到新数组，并正确清零、执行写屏障。

6.1 逻辑容量 nextslicecap

源码见 nextslicecap#L325-L358：

if newLen > 2*oldCap {
    return newLen
}
if oldCap < 256 {
    return 2 * oldCap
}
for newcap < newLen {
    newcap += (newcap + 3*256) >> 2
}

这不是“永远 2 倍”或“超过阈值立刻固定 1.25 倍”。公式从 2 倍平滑过渡，容量越大越接近 1.25 倍。

oldCap公式得到的下一逻辑容量（一次迭代）比例

很大约 1.25*oldCap + 192趋近 1.25

IMPORTANT

实际 cap 还会变化 growslice 会按元素宽度和内存分配器的 size class 调整字节数，所以最终 cap 可能大于 nextslicecap 的逻辑结果。不要把容量序列当作稳定 API。

6.2 指针元素与无指针元素

源码在 growslice#L203-L284 分开处理：

  • 无指针元素使用 noscan 分配，append 即将覆盖的区域可以不先清零；
  • 含指针元素必须给 GC 可扫描的零初始化内存；
  • 搬运指针时需要批量写屏障；
  • 最后统一 memmove 旧数据。

零大小元素使用全局 zerobase，见 slice.go#L195-L199。

7. copy、clear 与 slices

7.1 copy 支持重叠

copy(dst, src) 返回 min(len(dst), len(src))，语义允许源和目标重叠。运行时最终使用支持重叠的 memmove，相关代码见 slicecopy#L391-L430。

s := []int{1, 2, 3, 4}
copy(s[1:], s[:3])
fmt.Println(s) // [1 1 2 3]

7.2 clear 只清可见长度

clear(s) // 将 s[:len(s)] 的元素设为零值，不改变 len/cap

删除含指针元素后应清理尾部，避免无用对象继续被底层数组引用。标准库 slices.Delete 已负责清零被移出的尾部。

7.3 Grow、Clip、Clone

  • slices.Grow：保证还能 append n 个元素；
  • slices.Clip：返回 s[:len(s):len(s)]，只限制容量，本身不复制；
  • slices.Clone：浅复制元素，切断底层数组别名。

WARNING

Clip 不等于释放多余内存 Clip 只让下一次 append 无法使用现有尾部容量；切片仍指向同一个底层数组。若要摆脱大数组保留，使用 Clone/copy。

8. 并发与内存模型

切片描述符和底层数组是两类共享状态：

  • 一个 goroutine append 并写回共享切片变量，另一个读取该变量：描述符数据竞争；
  • 两个 goroutine 写共享底层数组同一元素：元素数据竞争；
  • 写互不重叠的元素可行，但切片长度、所有权和生命周期必须已经安全发布，且不能并发扩容改变共享描述符。
go test -race ./...

API 设计上优先明确所有权：只读借用、调用方保留、被调用方接管，或返回新切片。模糊的别名关系比扩容算法更容易制造生产事故。

9. 性能与容量治理

9.1 已知数量就预分配

out := make([]Item, 0, len(input))
for _, x := range input {
    out = append(out, transform(x))
}

预分配减少扩容、复制和 GC 压力；不要无依据给出极大 cap，否则只是把峰值内存提前并长期保留。

9.2 观察真实分配

go test -bench=. -benchmem ./...
go test -run='^$' -bench=BenchmarkBuild -memprofile=mem.out
go tool pprof -alloc_space mem.out
go build -gcflags='-m=2' ./...

生产指标建议关注：请求对象大小分布、批次元素数、分配速率、堆峰值、GC CPU、P99 延迟和 OOM 前的 RSS。

10. 常见误区

[!failure] append 一定修改原切片 append 可能复用原数组，也可能换数组；必须接收返回值。

[!failure] 复制切片就复制了数据 b := a 只复制三个字段。需要独立数据使用 slices.Clone 或 copy。

[!failure] cap 是已经初始化的元素数 cap 只是允许切片扩展的上界；合法索引仍必须小于 len。

[!failure] 只要最终 len 很小就不会占大内存 小子切片可能保留大底层数组；应结合所有权和生命周期主动复制。
