数组：Go 1.26.5 源码分析

[!abstract] 一句话理解 Go 数组是“长度属于类型、元素连续存放、赋值会复制”的值类型。它没有运行时数组头；长度和元素类型在编译期已经确定，运行时只需要一段连续的元素存储。

本文以 Go 1.26.5、提交 c19862e5f8415b4f24b189d065ed739517c548ba 为准。相关主题：切片、字符串、内存分配器、垃圾收集器。

1. 先建立完整模型

数组最重要的四条语义：

  1. [3]int 与 [4]int 是不同类型；
  2. 数组变量保存完整值，赋值、传参和返回通常表现为整值复制；
  3. len([N]T) 和 cap([N]T) 都是 N；
  4. 元素在内存中连续排列，元素地址可按 base + i*sizeof(T) 计算。
var a [3]int
b := a
b[0] = 9
fmt.Println(a[0]) // 0：b 是 a 的副本

2. 类型系统中的数组

编译器用元素类型和长度共同描述数组。源码位置：cmd/compile/internal/types/type.go#L391-L400、NewArray#L520-L534。

type Array struct {
    Elem  *Type
    Bound int64
}

运行时的类型元数据同样保存元素类型和长度，见 internal/abi.ArrayType#L268-L280：

type ArrayType struct {
    Type
    Elem  *Type
    Slice *Type
    Len   uintptr
}

这里的 Slice 是对应的 []T 类型元数据，不是某个数组值附带的切片。数组值自身没有 Data/Len/Cap 头部。

2.1 长度为什么属于类型

长度进入类型后，编译器可以在运行前完成：

  • 占用空间计算：N * sizeof(T)，同时检查溢出；
  • 对齐和 GC 指针位图生成；
  • 常量下标检查；
  • len、cap 常量折叠；
  • 数组是否可比较、如何比较；
  • 小固定长度操作的展开和边界检查消除。

NOTE

可比较性 数组只有在元素类型可比较时才可比较，也才能作为 map 的键。比较按索引顺序比较所有元素；[0][]byte 的长度虽然为 0，但元素类型不可比较，因此该数组类型仍不可比较。

3. 初始化与复合字面量

var zero [4]int                  // 全部为零值
a := [4]int{1, 2}               // [1 2 0 0]
b := [...]int{1, 2, 3}          // 编译期推导为 [3]int
c := [...]string{2: "tail"}     // 推导为 [3]string
d := [5]int{1: 10, 4: 40}       // 指定索引初始化

[...]T 只允许用于数组复合字面量，长度由最大索引和元素数量在编译期确定，不存在运行时“动态数组长度”。复合字面量在编译器中由 fixedlit 处理；常量部分可以进入静态数据，动态表达式则生成运行时代码。

数组放在栈、全局区还是堆，不由数组语法决定，而由作用域、大小和逃逸分析共同决定。可用下面的命令观察：

go build -gcflags='-m=2' ./...

4. 内存布局

以 64 位平台上的 [4]int32 为例：

元素地址满足：

addr(a[i]) = addr(a[0]) + uintptr(i) * sizeof(T)

数组的总大小还受元素对齐和类型尺寸规则约束。数组元素本身已经按其类型大小包含尾部填充，所以相邻元素可以直接按元素 Size 排列。

type Item struct {
    A byte
    B int64
}

var x [3]Item
fmt.Println(unsafe.Sizeof(x))

TIP

内存优化顺序 先优化元素结构体字段布局，再考虑数组长度。元素每节省 8 字节，百万元素数组就节省约 8 MiB。

5. 索引、切片与边界检查

数组索引最终对应“边界检查 + 地址计算 + 读写”。常量越界会在编译期报错；变量下标不能证明安全时，生成运行时检查。

func at(a [8]int, i int) int {
    return a[i] // 需要证明 0 <= i < 8
}

编译器可以通过循环条件消除重复检查：

for i := 0; i < len(a); i++ {
    sum += a[i]
}

查看边界检查是否残留：

go build -gcflags='-d=ssa/check_bce/debug=1' ./...

从数组得到切片时不会复制元素，只创建一个指向数组存储的切片描述符：

a := [5]int{1, 2, 3, 4, 5}
s := a[1:4] // len=3 cap=4，共享 a 的存储
s[0] = 20
fmt.Println(a[1]) // 20

当前语言还支持从切片转换为数组或数组指针；若切片长度小于目标数组长度，运行时 panic：

s := []byte{'a', 'b', 'c'}
a := [3]byte(s)       // 复制成数组值
p := (*[3]byte)(s)    // 指向同一底层存储

6. 复制、传参与 range

6.1 赋值和传参

func mutateValue(a [1024]int) { a[0] = 1 }   // 接收副本
func mutatePtr(a *[1024]int) { a[0] = 1 }    // 修改原数组
func mutateSlice(a []int)    { a[0] = 1 }    // 共享底层数组

大数组按值跨函数边界会增加复制成本，也会扩大栈帧。API 通常使用 []T 表达序列；只有长度是协议的一部分时使用数组，例如 [16]byte UUID、[32]byte 摘要。

编译器不一定真的调用逐元素复制：根据类型和大小，它可能内联若干 load/store，或降为 memmove。语义始终是完整值复制。

6.2 range 的求值语义

range 表达式只求值一次。遍历数组值时，range 保存的是数组值，因此对源数组的后续修改未必影响迭代值；遍历数组指针或切片则继续引用原存储。

a := [3]int{1, 2, 3}
for i, v := range a {
    if i == 0 { a[1] = 99 }
    fmt.Println(v) // 1 2 3
}

编译器对数组、数组指针和切片的 range 降级路径见 walk/range.go#L100-L239。核心形态是：缓存长度、维护索引，并在需要值时读取当前元素。

7. GC 与逃逸

数组是否被 GC 扫描取决于元素是否含指针：

  • [N]byte、[N]int 属于 noscan 数据；
  • [N]*Node、[N]string、[N][]byte 含指针，GC 必须扫描相应指针位；
  • 数组越大、指针密度越高，扫描成本越明显。

WARNING

大数组局部变量 “声明在函数里”不等于一定在栈上。大对象、被闭包捕获、地址逸出或生命周期跨越调用边界时都可能进入堆。以 -gcflags='-m=2' 的实际结果为准。

8. 生产实践

8.1 适合使用数组

  • 固定宽度协议字段、哈希、密钥和 nonce；
  • 需要数组作为 map key；
  • 小型查表和固定维度数学数据；
  • API 需要编译期表达“必须恰好 N 个元素”。

8.2 更适合使用切片

  • 长度由输入决定；
  • 需要 append、截取、共享窗口；
  • 大序列需要避免按值复制；
  • API 希望接收多种长度。

8.3 基准和诊断

go test -bench=. -benchmem ./...
go test -gcflags='-m=2' ./...
go tool objdump -s 'pkg\.Function' ./binary

重点观察：ns/op、B/op、allocs/op、栈帧大小、逃逸原因以及是否出现不必要的数组复制。

9. 常见误区

[!failure] 数组变量只是一个指针 错。数组变量保存整个数组值；只有 *[N]T 才是数组指针。

[!failure] [N]T 和 []T 只差一个固定长度 错。前者是值本身，后者是三字的描述符，并可能与其他切片共享底层数组。

[!failure] range 的第二个变量是元素引用 错。v 是每轮赋值得到的值。需要修改元素时使用 a[i]。

[!failure] 固定长度就一定更快 不一定。数组可能触发大块复制；切片多一次间接访问，但能避免复制。以真实基准为准。
